# Parallel Execution

## Eligibility

Parallelize only when lanes have independent inputs and disjoint write ownership. Keep blocking discovery and tightly coupled design local.

## Method

1. Split work by concrete output, not vague role.
2. Assign each lane exact files or responsibility boundaries.
3. State shared invariants and forbidden edits.
4. Give each lane its own focused verification.
5. Continue non-overlapping local work while lanes run.
6. Review returned changes before integration.
7. Resolve conflicts at the canonical owner, not by duplicating behavior.
8. Run combined verification after all lanes merge.

## Guardrails

- Do not delegate the next blocking step merely to appear parallel.
- Do not have multiple lanes inspect or edit the same unresolved area.
- Do not accept summaries without checking produced files or evidence.
- Close completed agents or worktrees when no longer needed.

## Output

Record lane ownership, results, integration changes, and combined verification.
