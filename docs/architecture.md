# Architecture

Use this document for the cross-cutting system architecture.

## Purpose

This file should explain the overall shape of the system and why the project is
designed the way it is.

## Fill This In For Your Project

Replace the starter text with project-specific guidance for:

- major components and boundaries
- integration points
- information flow or control flow
- architectural rationale and tradeoffs

## Recommended Sections

### Major Components

Describe the core parts of the system and what each owns.

### Boundaries And Responsibilities

Explain where responsibilities split.

### Integration Points

Call out important external systems or internal interfaces.

### Flow

Describe how information or control moves across the system.

### Rationale

Explain why the system is shaped this way.

## Boundary

Keep cross-cutting architecture here. Feature-local or stage-local detail should
move to deeper owning docs when the subject is no longer truly global.
