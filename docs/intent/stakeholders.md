# Stakeholders

## Primary Stakeholders

- **Project builder / maintainer**
  - needs a repo that stays understandable as product code, docs, and workflows grow
- **Operator / teammate**
  - needs explicit governance, routing, and handoff boundaries
- **Reviewer / auditor**
  - needs to know where the real source of truth lives for behavior, docs, and process
- **Future contributor or agent**
  - needs stable doc ownership and planning rules instead of reverse-engineering repo habits
- **Public reader**
  - needs a curated product-facing surface when the project also has private operating material

## What They Need

- clear ownership of purpose, method, system meaning, and execution artifacts
- a repo that resists source-of-truth drift
- reusable governance patterns instead of one-off conventions
- explicit private/public boundaries when publication is needed
- docs that point to the owner of each fact rather than competing with each other
