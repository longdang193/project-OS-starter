# Optional Project Roadmap

Use this file only when several outcomes need coordinated direction. Ordinary
work may start from approved user scope, an issue, a specification, or an
implementation plan without entering this roadmap.

## Goal

Keep the private starter source, generated starter kit, and reusable operating
methods coherent without turning the roadmap into a task tracker.

## Current Outcomes

### Lean Intent-To-Execution Flow

- keep brainstorming, specifications, and plans conditional
- let implementation plans own task order, execution approach, required skills,
  parallel-safe lanes, shared-write controls, and verification design
- preserve evidence-first execution, completion verification, and authorized
  branch finishing

### Starter Adoption Quality

- keep starter adoption understandable for new projects
- keep generated starter output least-privilege and reproducible
- keep prompt and guidance surfaces discoverable without duplicated governance

### Private/Public Boundary

- keep private development truth in `project-OS-starter`
- publish only curated allowlisted output
- keep generated and synchronized starter surfaces derived from canonical source

## Later

- add outcomes only when they need coordination across several specs or plans
- remove outcomes when completed or no longer useful

## Completion Criteria

Roadmap completion is a maintainer decision based on its listed outcomes. It
does not require child workstreams, threads, checkpoints, specs, or plans.
